# W201 Repetition of an expression that can match nothing

A repeated expression can match the empty string. A step that matches nothing would match nothing again, so the repetition ends with it, whatever its count asks for. That is seldom meant: where the expression matches nothing, the repetition stops and does not go on to what a later step could have matched.

```fpeg
start: (NAME? ","?)* ";"
NAME: [a-z]+
```

```text
grammar.fpeg:1:8: warning[W201]: this repetition ends at the first step that matches nothing, which its expression can
```

Give every step something it must match, and move what is optional around the repetition.

```fpeg
start: (NAME ","?)* ";"
NAME: [a-z]+
```

The warning is given where the expression, or one alternative of it, is built of optional parts alone. A part that looks ahead or depends on flags, columns or captures may fail where the others match nothing, so an expression that needs such a part is not reported. Neither is an alternative behind one that may pass a cut or fail an error label, which can end the choice before it. A rule that the expression calls counts as it matches: an error label inside it is not looked at, and where such a label ends the parse before the alternative that matches nothing, the warning is wrong.
